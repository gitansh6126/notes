What kind of topic this is

A comparative landscape, not a single spec to master. The useful skill is knowing which format a task calls for — human long-form writing, machine-to-machine data, or code plus documentation together — not memorizing every syntax rule.

Concept 1

Why HTML Still Dominates

Not because it's the cleanest format — because it keeps evolving and rarely breaks.

Living Standard

Continuously updated to meet modern needs, rather than frozen at a fixed spec version.

Extensibility

Web Components and JS APIs let developers define new tags and behavior without leaving HTML.

Semantic Focus

Separates content (HTML) from presentation (CSS) — simpler in practice than legacy SGML/XML.

Forgiveness

Browsers render imperfectly structured HTML rather than rejecting it outright.

✓
Why "forgiveness" matters

A strict format like XML fails an entire document over one mismatched tag. HTML's browsers render around the error instead — a deliberate trade-off favoring resilience over correctness.

Concept 2

Where HTML Falls Short

Dominance in one job doesn't mean fitness for every job.

LimitationWhy it's a problemWhat's used instead
Machine-to-machine dataTags add parsing overhead a program doesn't needJSON
VerbosityTags overwhelm long-form human writingMarkdown / RST / AsciiDoc
3D / VR spaceNot designed to describe spatial geometryVRML → X3D
⚖
The underlying rule

Use HTML when humans and browsers render the content. Use JSON when machines exchange it. Neither format is "better" in general — they're optimized for different readers.

Concept 3

Text-Based Markup Languages

Markdown, RST, and AsciiDoc trade strict nesting rules for characters a human can type without thinking.

WantHTMLMarkdown
Bold text<strong>text</strong>**text**
Heading<h1>Title</h1># Title
List item<li>item</li>- item

Advantages

Human-readable even unrendered · Long-lived, since plain ASCII/Unicode doesn't rot like proprietary word-processor formats · Compact to store and send.

Disadvantages

Ambiguous compared to XML/HTML's strict nesting — mismatched delimiters can render unpredictably · Inconsistent handling of tables and non-Western scripts across implementations.

A
Analogy

HTML is a legal contract — every clause explicit, unambiguous, verbose. Markdown is a handwritten note — quick to write, easy to read, but two people might format a nested list slightly differently.

Concept 5

Literate Programming

Pioneered by Knuth's WEB system: write the explanation and the code in the same document, then extract both.

Exam trap

"Literate programming failed and is irrelevant today" — overstated. The classic WEB-style workflow didn't take off broadly, but its core idea — markup and code intertwined in one file — is exactly what JSX and Vue templates do daily.

Connections & recall

Where this fits, and where it's misread

Connects to: the "structured data" theme from earlier lectures — JSON was preferred for machine-to-machine exchange in both the REST and GraphQL discussions, for the same reason lightweight markup is preferred for human writing: match the format to who's actually reading it.

!
Exam trap

"Markdown will eventually replace HTML" — false. They solve different problems: Markdown is for human authoring, HTML is the rendered, interactive, browser-executed target. Markdown documents are routinely compiled to HTML, not instead of it.

Active recall

Why does HTML's "forgiveness" matter architecturally?
It trades strict correctness for resilience — a browser renders around a malformed tag instead of failing the whole page, unlike strict formats such as XML.
Name one advantage and one disadvantage of lightweight markup versus HTML.
Advantage: human-readable even unrendered, and long-lived since it's plain text. Disadvantage: more ambiguous than HTML/XML's strict nesting — things like mismatched delimiters or complex tables can render inconsistently.
What's the actual connection between classic literate programming and JSX?
Both intermix human-facing content (prose or markup) with executable logic in a single file, extracted or compiled into separate outputs — the same underlying idea, decades apart.
Recap

The whole lecture, compressed

Core Intuition

Match the format to who's reading: browsers, humans typing, or machines parsing.

HTML Wins Because

Living standard, extensible, semantic, forgiving.

HTML's Limits

Too verbose for long writing, wrong tool for machine data or 3D space.

Lightweight Markup

Markdown / RST / AsciiDoc — readable raw, long-lived, compact, but ambiguous.

Tooling

Pandoc converts across formats so teams don't standardize on just one.

Literate Programming

Docs + code, one file → compiler extracts both.

Modern Echoes

Doxygen (docs from comments), JSX/Vue (markup + logic intermixed).

Never True

"Markdown replaces HTML" — it compiles to it.

Decision Rule

Human long-form → Markdown/RST/AsciiDoc. Machine data → JSON. Rendered/interactive → HTML.
