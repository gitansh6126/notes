Module 2 · Core Intuition

Why does this exist?

In the hybrid setup (8.2), Vue and Jinja lived in the same house. Now imagine splitting into two separate buildings entirely — a restaurant's dining room (Vue frontend) and its kitchen (Flask backend) — connected only by waiters carrying orders back and forth (API calls). The kitchen doesn't care who's sitting at the table; it just receives orders and sends back food (JSON data).

🍽️ Analogy
Because the dining room and kitchen are now different buildings (different ports/domains), the building's security guard (the browser's Same-Origin Policy) stops any waiter from freely walking between them — unless the kitchen puts up a sign explicitly saying "waiters from this dining room are allowed in." That sign is CORS.

Module 5 · Deep Fundamentals

The four core questions

1. Why was this feature created?

As apps grow, teams want to scale, deploy, and develop the frontend and backend independently — different teams, different release cycles, sometimes even different hosting providers (e.g. frontend on a CDN, backend on a cloud server).

2. What problem does it solve?

It removes the tight coupling from the hybrid model. Flask becomes a pure API server; Vue becomes a pure client app. Either can be redeployed, scaled, or replaced without touching the other.

3. What happens internally?

The browser loads the Vue app from one origin (e.g. a CDN or a dev server on port 8081). When Vue's JS code makes a fetch/axios call to Flask's API on a different origin (port 8080), the browser's Same-Origin Policy checks whether the response includes CORS headers permitting that origin — if not, it blocks the response from reaching Vue's JS.

4. How does the browser execute it?

For non-trivial requests, the browser first sends a "preflight" OPTIONS request asking the backend "will you accept a request from this origin?" Only if Flask (via flask-cors) answers yes does the browser allow the actual request to proceed.

Module 7 · Syntax Anatomy

Breaking down the pieces

app.py — enabling CORS
from flask_cors import CORS

app = Flask(__name__)
CORS(app, origins=["http://localhost:8081"])
  • CORS(app, ...) wraps the whole Flask app so every route can respond with the right cross-origin headers
  • origins=[...] the allow-list — in dev this is often "*" (allow everyone); in production it must be your exact frontend domain
Module 8 · Code Walkthrough

Step by step, with annotations

Step 1 — Enable CORS in development

app.py
from flask_cors import CORS
CORS(app)  # dev only: allows all origins

Step 2 — Frontend calls the API with a token

Vue component — fetching data
fetch("http://localhost:8080/api/items", {
  headers: { "Authentication-Token": this.token }
})
  .then(res => res.json())
  .then(data => { this.items = data })
  • Authentication-Token header replaces cookies since the two apps don't share a domain, so browsers won't auto-send cookies across origins anyway

Step 3 — Build the Vue app for production

Terminal
npm run build  # generates a /dist folder with compiled HTML/CSS/JS

Step 4a — Separate deployment (Vue on CDN, Flask standalone)

Upload dist/ to a static host or CDN. Flask stays a pure API server elsewhere. Update CORS origins to that CDN's domain.

Step 4b — Combined deployment (Vue served by Flask)

app.py — serve Vue's dist folder + redirect root
app = Flask(__name__, static_folder="dist", static_url_path="")

@app.route("/")
def index():
    return app.send_static_file("index.html")
  • static_folder="dist" points Flask at Vue's compiled output instead of its usual static folder
  • static_url_path="" serves those files from the root URL rather than under /static
  • @app.route("/") redirect controller — ensures visiting the base URL lands on Vue's index.html, not a 404
  • Don't forget: also adjust Vue's publicPath config so its built asset URLs match where Flask actually serves them from
Module 9 · Behind the Scenes

What the browser actually does

JS calls fetch() to a different origin
→
Browser sends preflight OPTIONS request
→
Server responds with Access-Control-Allow-Origin
→
If matched → real request proceeds; else → blocked
⚠️ CORS is enforced by the browser, not the server
The Flask server may actually process and respond to the request just fine — but if the response headers don't permit the calling origin, the browser throws away the response before your JS code ever sees it. Tools like Postman ignore CORS entirely, which is why "it works in Postman but not in the browser" is a classic CORS symptom.

Module 11 · Common Mistakes

Wrong vs Right

❌ Wrong
Relying on cookie-based authentication between a frontend on port 8081 and a backend on port 8080 — cookies typically won't be sent across different origins by default.
✅ Correct
Use Auth Tokens sent explicitly in request headers — they don't depend on the browser's cookie/session behavior at all.
❌ Wrong
Leaving CORS set to allow all origins ("*") in a production deployment — a security risk since any website could call your API.
✅ Correct
Restrict origins to your actual frontend's exact production domain before deploying.
❌ Wrong
Forgetting to update Vue's publicPath and Flask's static_folder together in combined deployment — leads to broken CSS/JS asset paths (blank white page).

Module 19 · Lecture Notes

Original Topic Content

This section contains the full original lecture content — the concepts, details, and explanations as taught in the screencast, outside the framework structure.

Overview

When Vue and Flask run on different ports or domains, the browser's Same-Origin Policy blocks API calls by default. CORS (Cross-Origin Resource Sharing) is the mechanism that loosens this restriction, and token-based authentication replaces cookies (which don't work across origins).

CORS

Cross-Origin Resource Sharing

  • Same-Origin Policy Browsers block requests where protocol + host + port don't all match. This is a security feature, not a bug.
  • Preflight (OPTIONS) For non-simple requests, the browser sends an OPTIONS request first to ask "is this allowed?" The server must respond with the right headers.
  • flask-cors CORS(app, origins=["http://localhost:5173"]) — tells Flask to include the correct CORS headers for your frontend's origin.
  • Browser-enforced CORS is enforced by the browser, not the server. Postman and curl ignore CORS entirely — that's why the API works in Postman but fails from the Vue app.
Auth Across Origins

Why Cookies Break and Tokens Fix It

Cookies are bound to a specific origin (domain). When Vue runs on localhost:5173 and Flask on localhost:5000, the browser won't send cookies to the Flask origin. Token-based auth solves this — the token is sent via an HTTP header (Authentication-Token: <token>), which the browser doesn't restrict by origin.

Deployment Patterns

Separate vs Combined Deployment

  • Separate Vue on a CDN/static host, Flask standalone. Independent scaling, better CDN performance, but two pipelines to manage.
  • Combined Vue's dist/ folder placed inside Flask's static/ folder. Simpler ops, one deployment pipeline, but no CDN benefit.
  • publicPath Vue's build config must align with Flask's static_folder path so asset URLs resolve correctly.
  • Root redirect Flask's @app.route("/") returns Vue's index.html so the SPA handles all client-side routing.
