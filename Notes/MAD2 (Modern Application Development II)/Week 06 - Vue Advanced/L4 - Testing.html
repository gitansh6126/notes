Overview

Testing is how you check a Vue component's behavior on purpose, instead of finding out by accident when a user files a bug report. Good tests confirm that components render the right thing, react correctly to input, and keep working when the app around them changes.

01

Core Testing Types

Three questions, three kinds of tests. Each one checks a different layer of "does this actually work?"

Unit Testing

Like inspecting a single Lego brick before it ever goes into the set.

Tests one component in isolation — its logic and behavior — without worrying about the rest of the app around it.

End-to-End (E2E)

Like test-driving the whole car, not just admiring the engine on a bench.

Runs the full application flow — UI, backend, database — simulating what a real user actually does.

Cross-Browser

Like trying the same pair of shoes in five different stores to make sure they always fit.

Confirms the app looks and works consistently across Chrome, Firefox, Safari, and Edge.

02

How the Three Fit Together

E2E — few, slow, whole app
Component-level checks
Unit — many, fast, isolated
Write lots of cheap unit tests, fewer expensive end-to-end tests.
⇄

Cross-browser testing isn't a layer in the pyramid — it's a sweep across every layer, checking that whatever you built also behaves the same way on someone else's browser.

Key Concepts & Tools

The cast of characters in a typical Vue test suite.

Tool / ConceptWhat it doesThink of it as…
Virtual Testing DOM Mounts a component into an in-memory DOM so you can inject data and simulate interaction without a real browser. a crash-test lab, not a real road
Vue Test Utils The official testing library — shallowMount renders a component, setData changes its state for testing. the manufacturer's own wrench set
Mocha Organizes tests into describe / it blocks and runs the suite. the stage manager calling each scene
Chai Assertion library — phrases like expect(x).to.equal(y). the referee deciding if it counts
Jest Combines a test runner, assertions, and mocking in one package. a Swiss Army knife for testing
Babel Transpiles modern JavaScript into a form older browsers can run, supporting cross-browser compatibility. a translator for browsers stuck in the past
04

What shallowMount Actually Does

It renders the component you're testing for real, but stubs out its children — so a bug in a child component can't make your test lie to you.

mount() — full render

<Hello> — fully rendered
<UsernameInput> — fully rendered
<ErrorBanner> — fully rendered
vs

shallowMount() — isolated

<Hello> — fully rendered
<UsernameInput-stub>
<ErrorBanner-stub>

Key Takeaways

    

      

        
Automate it

        
Manual click-through testing doesn't scale and isn't repeatable. Automated tests give consistent, reliable results every run.

      

      

        
Test both layers

        
Check the DOM output and the underlying JS logic — a component can look right while its logic is broken, or vice versa.

      

      

        
Suites scale apps

        
In large apps, one state change can ripple across many components. A robust test suite is what makes that safe to build on.
