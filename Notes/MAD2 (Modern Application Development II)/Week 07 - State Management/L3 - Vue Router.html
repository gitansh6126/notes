00

From Pages to Components

On the traditional web, the browser fetches a brand-new HTML page from the server for every click — and reloads everything. In a Vue app, the page is built from components: navigating doesn't reload the page, it just swaps which component is rendered. This is the foundation of a Single Page Application (SPA).

01

The Two Building Blocks

Vue Router runs entirely in the browser — no server round-trip needed for every link click.

<router-link to="/"> <router-link to="/about"> <router-link to="/contact">
<router-view> — renders whatever matches the active path <About />

<router-link> renders as an <a> tag but intercepts the click — it updates the route state instead of reloading. <router-view> is the placeholder that reacts to that state and renders the matching component.

02

A route config is just a map — path in, component out.

03

Dynamic Routing

Part of the path can be a variable, captured for the component to use.

/user/:id → navigate to /user/42 → read via $route.params.id
⚠

Reactivity gotcha: going from /user/1 to /user/2 often reuses the same component instance instead of recreating it. If the UI doesn't update, add a watcher on $route to detect the change and refresh manually.

04

Advanced Features

Nested Routes

A <router-view> inside another component, enabling sub-navigation.

Named Routes

Reference routes by name instead of hardcoded paths — easier to read and maintain.

Named Views

Render multiple components into different <router-view> elements at once.

History Mode

Uses the browser's History API so the back button works like a native app, despite being an SPA.

05

Benefits & Trade-offs

Benefits

  • Smoother, desktop-like user experience
  • Only the changed part of the page updates
  • Fewer full fetches — more efficient overall

Trade-offs

  • The server has no idea client-side navigation happened
  • Browser history management gets more complex
  • Component reuse can cause reactivity bugs
06

Key Takeaways

Swap, don't reload

SPAs replace components in place instead of asking the server for a whole new page.

Params aren't automatic

Dynamic segments land in $route.params — but reused components may need a watcher to react to them changing.

Client-side ≠ server-blind by choice

The smoother UX comes with a real trade-off: the server no longer knows what page the user thinks they're on.
