What Is "State"?

Application state is the collection of variables at the frontend that represents the current UI. Declarative programming treats the interface as a direct, predictable output of that state — nothing more.

UI = f(state) change the state, the view redraws itself — you never touch the DOM by hand
02

The Problem With Deep Component Trees

Vue components form a tree. Passing data between distant nodes means shoving it through every component in between — even ones that don't care about it.

App

03

Global Variables vs. Controlled Stores

A global variable solves the drilling problem — but opens a worse one.

Plain Global Variable

Sidebar → mutates Menu → mutates Modal → mutates

Any component can change it, from anywhere, at any time. When something breaks, there's no single place to look — like a shared whiteboard everyone scribbles on with no eraser log.

Controlled Store

Sidebar → action Menu → action
⇣ dispatch ⇣

Components can only request a change through a defined action. One gate, one source of truth — like a bank teller window instead of an open vault.

04

Where Vuex Comes From

Vuex didn't appear in a vacuum — it borrows from a small family of state-management ideas.

PatternCore ideaThink of it as…
Flux (Facebook) A store, a dispatcher, and strictly unidirectional data flow for React apps. a one-way conveyor belt, not a two-way street
Redux State is read-only; changes only happen through pure functions, which keeps outcomes predictable and easy to debug. a ledger you can only append to, never erase
Elm Architecture A functional loop of model (state), view (HTML), and messages (updates) — small and minimal by design. a thermostat: read temp → decide → adjust → repeat
Vuex Vue's own take on the same idea: one global, restricted-access store as the app's single source of truth. these ideas, tailored to Vue's component tree
05

Key Takeaways

One direction only

State drives the view, the view triggers actions, actions update state. Never skip the cycle — that's what keeps it debuggable.

Build the mental model

The point of these patterns isn't ceremony — it's giving you one clear, predictable picture of how data moves through the app.

Centralize to scale

Letting children mutate parent data directly doesn't scale. A centralized, predictable store is what lets an app grow without breaking itself.
