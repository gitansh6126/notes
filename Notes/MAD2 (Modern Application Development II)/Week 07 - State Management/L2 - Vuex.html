00

Overview

Vuex is Vue's official state management library. Instead of every component guarding its own slice of data, Vuex gives the whole app one centralized, global store — making data interactions predictable and easy to reason about, even as the app grows.

01

Anatomy of a Store

Five pieces, each with exactly one job.

container

Store

The single shared container holding the app's entire state, reachable anywhere via this.$store.

data

State

Replaces component-level data(). A tree that mirrors the component hierarchy.

read

Getters

Derive and access state values conveniently — like a computed property for the whole store.

sync

Mutations

The only legal way to change state. Always synchronous. Triggered with commit().

async

Actions

Handle async logic, then commit a mutation once it resolves. Triggered with dispatch().

02

Mutations vs. Actions

The split exists for one reason: keeping state changes traceable.

Mutations

store.commit('setUser')
instant, synchronous

Change state directly and immediately. Because they're synchronous, dev tools can record each one in order — the foundation of time-travel debugging.

Actions

store.dispatch('fetchUser')
waits, then commits

Wrap async work — API calls, timers — and only commit a mutation once that work resolves. They never touch state directly.

03

Why Mutations Must Be Synchronous

Every commit is recorded in order — so dev tools can scrub backward and forward through your app's history.

If a mutation were async, its exact position in this timeline would be unpredictable — breaking the recording that time-travel debugging depends on. That's why the rule is strict, not stylistic.

04

When Should You Reach for Vuex?

Good fit

  • Large or complex applications
  • Deeply nested component data
  • Multiple, unrelated components needing the same state

Skip it

  • Small, simple applications
  • State only used by one or two nearby components
  • Component-level state is already easy to manage
05

Key Takeaways

One store, one truth

Vuex centralizes state so every component reads from — and requests changes to — the same shared source.

Async lives in actions

Actions handle the waiting; mutations handle the change. Keeping them separate is what makes state changes traceable.

Complexity is a trade-off

Vuex earns its keep in large apps with shared, nested state — not in every project by default.
