The Decision Function of Naive Bayes

Naive Bayes was built as a generative model — but underneath the products and probabilities, it's secretly drawing a straight line. This lecture uncovers that line algebraically.

The Real-World Problem

Every prediction in L48 required us to recompute two full products of probabilities — one per class — and compare them. That's correct, but it hides a deeper question: what does the decision boundary actually look like in feature space? Is it curved, jagged, or something simple?

⚠️
Why this matters: if we can show Naive Bayes draws a straight line (a hyperplane) between spam and non-spam, we gain a much cheaper way to classify — just one dot product — and a direct comparison point against discriminative linear models like logistic regression.

Starting Point — The Decision Rule

Naive Bayes Prediction Rule
P(Y=1 | Xtest)  ≥  P(Y=0 | Xtest)   ⟹   predict Y=1
Eq. 1.1
💡
Instead of comparing two numbers directly, we'll study their ratio. A ratio ≥ 1 says the same thing as "left side ≥ right side" — and a ratio is much easier to simplify with logs, because a product's log becomes a sum.
3

Mathematical Translation — Log-Odds

Log-Odds Form of the Decision Rule
log
P(Y=1|X)
P(Y=0|X)
  ≥  0
Eq. 3.1
log-odds— the log of the ratio of posteriors. Positive → class 1 is more likely; negative → class 0 is more likely; exactly 0 is the tie-breaking boundary.
🧠
Why "≥ 0" instead of "ratio ≥ 1": log is monotonically increasing, so log(ratio) ≥ log(1) = 0 says exactly the same thing as ratio ≥ 1 — but now we're working with a sum instead of a product, which is what we actually want to simplify.
6

Full Derivation — From Log-Odds to a Straight Line

Every step, and why it happens
1
Apply Bayes' Rule to both posteriors
log-odds = log P(X|Y=1) − log P(X|Y=0)  +  log P(Y=1) − log P(Y=0)
P(Y|X) = P(X|Y)P(Y) / P(X). The P(X) in the denominator is identical for both classes, so it cancels the moment we take a ratio.
2
Substitute class conditional independence
log P(X|Y) = Σi [ fi log PY,i + (1−fi) log(1−PY,i) ]
Each binary feature is Bernoulli(P_{Y,i}): its log-probability is f_i·log P + (1-f_i)·log(1-P) — this expression equals log P when f_i=1 and log(1-P) when f_i=0, compactly written with the indicator built into the exponent form.
3
Subtract the class-0 sum from the class-1 sum
Σi fi [log P1,i − log P0,i]  +  (1−fi) [log(1−P1,i) − log(1−P0,i)]
Group terms feature-by-feature since the sums run over the same index i — this keeps every f_i attached to its own coefficient, which is exactly what we need for a linear form.
4
Expand (1 − f_i) and collect f_i terms
Σi fi · log
P1,i(1−P0,i)
P0,i(1−P1,i)
  +  Σi log
1−P1,i
1−P0,i
The f_i terms factor out into one clean log-ratio each — this ratio is exactly what becomes the weight w_i. What's left over (no f_i attached) is a pure constant, independent of the test point.
5
Reassemble with the prior log-odds
log-odds  =  Σi fi wi  +  [ Σi log(1−P1,i)/(1−P0,i) + log P̂/(1−P̂) ]
Bring back the log P(Y=1) − log P(Y=0) term from Step 1 (the prior log-odds) and fold it into the constant. Everything without an f_i attached — including this prior term — becomes the bias b.
✅
Result: the log-odds is exactly of the form wTX + b — a weighted sum of the features plus a constant. That's the defining shape of a linear classifier.
5

Formula Anatomy — The Linear Decision Function

Naive Bayes as a Linear Classifier
wTXtest + b  ≥  0   ⟹   predict Y=1
Eq. 5.1
Weight for feature i
wi  =  log
P̂1,i (1 − P̂0,i)
P̂0,i (1 − P̂1,i)
Eq. 5.2
wi— how much evidence feature i (a word) contributes toward "spam" vs "not spam"
P̂1,i— probability word i appears, given the email is spam
P̂0,i— probability word i appears, given the email is not spam
b— bias: everything that doesn't depend on the specific test point — leftover per-feature constants plus the class prior log-odds

Worked numerical example

Take the word "lottery": P̂1,lottery = 0.70 (appears in 70% of spam), P̂0,lottery = 0.05 (appears in 5% of non-spam).

StepComputationValue
Numerator0.70 × (1 − 0.05)0.665
Denominator0.05 × (1 − 0.70)0.015
wlotterylog(0.665 / 0.015)≈ 3.79

A large positive weight — the presence of "lottery" pushes the score strongly toward spam. A word equally likely in both classes would get wi ≈ log(1) = 0, contributing nothing to the decision.

Geometric Picture — What "Linear" Actually Looks Like

📏
Even though Naive Bayes was derived from probabilities and independent coin flips, the boundary it draws between the two classes is a straight hyperplane — geometrically identical in shape to what logistic regression or a linear SVM would draw, even though each gets there by a completely different route.

Data efficiencyOften needs less data (strong assumptions help)Often needs more data, but fewer assumptions
🌉
The bridge: this derivation shows Naive Bayes isn't a fundamentally different kind of classifier from logistic regression — it's a linear classifier whose weights happen to have a closed-form, counting-based formula instead of being learned iteratively.

Edge Cases & Scope

🔢 Binary features only

This exact linear derivation relies on each f_i being Bernoulli (0/1). With continuous features (e.g. Gaussian Naive Bayes), the algebra produces a different — generally quadratic — decision boundary. A future lecture extends this.

♾️ Undefined weights

If P̂0,i or P̂1,i is exactly 0 or 1, wi involves log(0) or division by 0 — another reason Laplace smoothing (L49) is a prerequisite here too.

Industry Implementation

import numpy as np

# Precompute w and b once from trained P_hat, P_1i, P_0i
w = np.log((P1 * (1 - P0)) / (P0 * (1 - P1)))
b = np.sum(np.log((1 - P1) / (1 - P0))) + np.log(P_hat / (1 - P_hat))

# Prediction is now a single dot product — no loop over words needed
def predict(X_test):
    return 1 if (w @ X_test + b) >= 0 else 0
🏭
This is exactly why production spam filters can classify an email in microseconds: once w and b are precomputed during training, prediction is a single vectorized dot product — identical in cost to a trained logistic regression model at inference time.
16

Invariant Library ⭐

Always True

With binary features, Naive Bayes' decision boundary is exactly linear — this is a mathematical identity, not an approximation.

Sometimes True

A feature with w_i ≈ 0 contributes little to the decision — happens when a word is equally common in both classes.

Never True

The boundary is never curved when features are strictly binary and independence is assumed — curvature only enters with continuous/Gaussian features.

Examiner Trap Library ⭐

🪤
Trap 1: assuming "generative model" and "linear classifier" are mutually exclusive categories. Naive Bayes is proof they aren't — a model can be generative in how it's trained and linear in what boundary it produces.
🪤
Trap 2: forgetting that b contains the class prior term, not just per-feature leftovers. If the classes are imbalanced (e.g. 95% not-spam), the prior shifts b and biases the decision even before any word is examined.
🪤
Trap 3: this linear result is specific to binary features. Don't generalize it to Gaussian Naive Bayes without re-deriving — that case yields a quadratic boundary in general.
19

Exam Shortcuts

  • Asked to prove linearity → start from log-odds ≥ 0, substitute independence, and group by f_i. Don't try to shortcut the algebra — examiners check the grouping step.
  • Asked for w_i → it's always a log-ratio of the form log[P1,i(1−P0,i) / (P0,i(1−P1,i))].
  • Asked what's in b → "everything without an f_i attached," including the prior log-odds.
