Cognitive Pattern

what kind of thinking is this?

This lecture is built on generative storytelling — literally imagining the random process (coin flips, dice rolls) that could have produced the data — paired with blunt counting. The punchline isn't a formula; it's an arithmetic gut-check that turns out to be devastating.

Problem Setup

turning an email into numbers

Binary classification: is an email Spam (Y = 1) or Not Spam (Y = 0)? To feed this to any algorithm, every email is converted into a fixed-length binary vector of dimension D — one entry per word in a predefined dictionary. Entry j is 1 if word j appears anywhere in the email, 0 if it doesn't.

Modelling Choices

two ways to factor P(X, Y)

Any joint distribution can be factored in two directions using the chain rule. Only one of them is actually generative.

Option A

P(X, Y) = P(X)·P(Y | X)

Requires modelling P(Y | X) directly — this is just the discriminative approach wearing a joint-distribution costume. It doesn't actually explain how spam differs from non-spam at the feature level.

Option B — chosen

P(X, Y) = P(Y)·P(X | Y)

Model the class prior P(Y) and, separately, the feature "recipe" P(X | Y) for each class. This is intuitive: it directly encodes what a typical spam email's words look like versus a typical legitimate one.

The Generative Story

an imaginary two-step machine that "produces" each email
FIG. 2 — flip a biased coin for the label, then roll a class-specific 2^D-sided die for the exact word pattern.
  1. Label generation: toss a biased coin with probability p to decide Spam (Y=1) or Not Spam (Y=0).
  2. Feature generation: given that label, roll an imaginary die with 2D faces — one face for every possible binary word-pattern — where the class determines how the die is weighted.
3

The Parameter Problem

counting what this story actually costs

A story is only useful if it can be learned from data — and learning it means estimating every free parameter it implies.

Step 1 — the coin
A single biased coin has exactly one free parameter: its bias p.
1 parameter
Step 2 — one die per class
A die with 2D faces needs 2D probabilities that sum to 1 — so only 2D − 1 are actually free. There are two such dice (spam, not spam).
2 × (2D − 1) parameters
Step 3 — total
Add the coin's one parameter to both dice.
Total = 1 + 2(2D − 1) = 2D+1 − 1

How big is 210,000, really? The number of atoms in the observable universe is roughly 1080. 210,000 is roughly 103,010 — larger than the atom count by about 2,930 orders of magnitude. There is no computer, and no amount of training data, that could ever estimate this many parameters.

Conclusion — A Correct but Useless Model

theoretically sound, practically dead

Nothing about this generative story is wrong. Modelling P(X | Y) with a fully general distribution over every possible word-pattern is a completely valid description of how spam and non-spam emails could be generated. The problem is purely practical: the number of free parameters grows exponentially in the number of features, and no realistic dataset could ever supply enough examples to estimate them.

Where the fix has to come from The only way forward is to give up on modelling every possible word-pattern independently, and instead make a simplifying assumption about how the words in a class relate to one another — trading a small amount of accuracy for an enormous reduction in parameters.
✓

Quick Recall

the whole lecture in one glance

Modelling P(X, Y) = P(Y)·P(X|Y) for spam detection means imagining a coin toss for the label and a 2D-sided die roll for the feature vector. That story requires 2D+1 − 1 parameters — for a realistic D = 10,000-word dictionary, an astronomically impossible number. The fully general generative model is correct in theory and unusable in practice.

Where This Leads

rescuing the generative approach

The next lecture introduces Naive Bayes — the same P(Y)·P(X|Y) story, rescued by assuming each word's presence is independent of every other word given the class. That single assumption collapses the parameter count from exponential to linear in D, turning an impossible model into one of the most practical classifiers in the course.
