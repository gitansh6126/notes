Cognitive Pattern

what kind of thinking is this?

This lecture is a shift from geometry to probability. Instead of asking "how close is this point to other points?" or "which question best splits the data?", it asks a more basic question first: what process produced this data in the first place — and is it worth the effort to model that process explicitly, or better to skip straight to the boundary?

0

The Learning Assumption

the idea every algorithm so far has quietly relied on

Every algorithm in this course — KNN, decision trees, and everything coming next — secretly leans on the same assumption: there exists some fixed, unknown distribution D over feature space X and label space Y. Both the training set and the test set are just independent samples drawn from that same D. Learning is the act of using the training sample to say something useful about D itself, so that predictions on the test sample — drawn from that same source — hold up.

Why this has to be true If training and test data came from genuinely different distributions, nothing learned from one would say anything reliable about the other. Every guarantee a learning algorithm offers is really a guarantee about D, inherited by both sets because they share the same source.
1

Two Schools of Modelling

what part of D does a model bother to learn?

Every classifier eventually needs to answer "given features X, what's the label Y?" — but algorithms differ sharply in how much of D they try to capture along the way.

Generative

Learns the joint distribution P(X, Y)

Models how features and labels are produced together — effectively learning a recipe for generating entire new examples, features included. The classification boundary falls out as a side-effect once you know P(X, Y) for every class.

Discriminative

Learns the conditional P(Y | X)

Never bothers modelling how X itself arose. It only learns the boundary needed to separate classes — nothing about what "generates" a typical member of one class versus another.

How a Generative Model Still Classifies

going from P(X, Y) back to a decision
Step 1 — decompose the joint
The joint distribution can always be factored using the chain rule of probability: the chance of a class, times the chance of seeing those features given that class.
P(X, Y) = P(Y) · P(X | Y)
Step 2 — this is exactly what a generative model estimates
P(Y) is the overall class frequency (a prior — e.g. "60% of students are in Football Team"). P(X | Y) is the feature "recipe" for each class — what a typical member looks like.
Step 3 — recover P(Y | X) when a prediction is actually needed
Bayes' theorem converts the learned joint distribution back into exactly the conditional a discriminative model would have learned directly.
P(Y | X) = P(X | Y) · P(Y) / P(X)
Formula · Bayes' Bridge
P(Y|X)  =  P(X|Y) · P(Y) P(X)
P(X|Y) the learned "recipe" for a class's features
P(Y) the class prior — how common each class is
P(X) the overall chance of seeing those features, any class
P(Y|X) the actual prediction target — same as a discriminative model's
The key insight A generative model does strictly more work than it needs to for classification alone — it learns the full joint distribution, then derives the boundary as a byproduct. A discriminative model skips straight to the part that classification actually requires.

Worked Example — Is This Sentence Bengali?

the lecture's own case study
Generative route

Build a model that understands Bengali deeply enough to actually generate plausible Bengali sentences — its grammar, its sound patterns, its structure. Once you can generate the language, telling it apart from anything else becomes almost automatic: whichever "recipe" more plausibly produced the sentence wins.

Discriminative route

Skip language modelling entirely. Learn to recognise the specific audio patterns that separate Bengali speech from everything else — without ever learning how to construct a single Bengali sentence.

The tradeoff, in one line The generative route only pays off if you actually have strong domain knowledge of how Bengali is structured. Get that generative model wrong, and the errors leak straight into your classifications — the discriminative route never has to be right about anything except the boundary.

Quick Recall

the whole lecture in one glance

All learning assumes training and test data share one fixed distribution D. Generative models try to learn the full joint P(X, Y) — a recipe for the data itself — and derive the boundary from it via Bayes' theorem. Discriminative models skip straight to P(Y | X), learning only the boundary. Choose generative when you trust your understanding of how the features arise; choose discriminative when you don't.
