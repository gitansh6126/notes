Rescuing the Generative Model — Naive Bayes

Cognitive Pattern

what kind of thinking is this?

The whole lecture rests on one move: trading a single hard question ("what's the joint probability of every possible word combination?") for D easy questions ("does this one word show up, yes or no?"), and simply multiplying the answers together. This is factorization — replacing one enormous unknown with many small, independent ones.

0

Recap — Where We Got Stuck

Lecture 46's dead end

Modelling the features of an email with one fully general 2D-sided die required 2D+1 − 1 parameters — for D = 10,000 words, computationally impossible. The die treated every one of the 2D possible word-combinations as needing its own separate probability, with no relationship assumed between them at all.

1

Class-Conditional Independence

the one assumption that fixes everything

The assumption: given the class label y, whether each individual word appears is independent of whether every other word appears. Not independent overall — only independent once you already know the class.

Implication, spelled out Knowing that an email is Spam and already contains the word "Lottery" tells you nothing extra about whether it also contains "Money" — under this model, each word's presence is decided by its own private coin, checked independently, once the class is fixed.
Why "naive" In real emails, words obviously do correlate ("Lottery" really does tend to show up alongside "Money" or "Winner"). Assuming otherwise is a simplification known to be technically false — which is exactly why this family of models is called Naive Bayes. It works remarkably well in practice anyway.

Mathematical Formulation

turning D independent coins into one formula
Step 1 — independence means "multiply"
If each word's presence is independent given y, the probability of the whole vector is just the product of each word's individual probability.
P(X | y) = P(f₁|y) · P(f₂|y) · … · P(f_D|y)
Step 2 — write it as a single term per word
Each word's coin has its own bias, p_{y,i} — the probability word i appears, given class y.
P(f_i | y) = py,i if f_i = 1,   (1−py,i) if f_i = 0
Step 3 — the exponent trick
Raising p to the power f_i (which is 0 or 1) is a compact way of writing an "if" statement: when f_i=1 the term is just p; when f_i=0 the term becomes 1, leaving only the (1−p) factor.
P(f_i | y) = py,if_i · (1−py,i)1−f_i
Formula · Naive Bayes Likelihood
P(X|y)  =  ∏i=1D py,ifi (1 − py,i)1−fi
X the full feature vector (f₁,…,f_D)
py,i probability word i appears, given class y
f_i 1 if word i is present, 0 if absent
∏ product over all D words
Full joint Combined with the class prior, the joint distribution the model set out to learn back in Lecture 46 is now: P(X, y) = P(y) · ∏ᵢ p_{y,i}^{fᵢ} (1−p_{y,i})^{1−fᵢ} — same target, dramatically fewer moving parts.

Quick Recall

the whole lecture in one glance

Assuming features are conditionally independent given the class replaces one 2D-sided die with D independent coins per class. The likelihood becomes a simple product, P(X|y) = ∏ py,if_i(1−py,i)1−f_i, and the total parameter count drops from 2D+1−1 to 2D + 1 — this is the Naive Bayes model.

Where This Leads

the model has parameters — now they need values

Having a manageable number of parameters is only useful once those parameters can actually be learned from training data. The next lecture introduces Maximum Likelihood Estimation (MLE) — the standard technique for turning a training set into concrete values for P(y) and every py,i.
