Goodness of the MLE for Linear Regression

We already know ŴML is the least-squares solution. Today's question is sharper: how close is it to the truth, on average?
How deep we're going: This lecture builds directly on two things you've already covered — the probabilistic view of linear regression and Maximum Likelihood Estimation. So we'll move quickly through Problem → History → Engineering setup, and spend the real depth on the derivation of 𝔼[‖ŴML − W‖²] = σ²·Tr((XᵀX)⁻¹) — that result, and what it implies about feature engineering, is the new content worth internalizing.

Cognitive Pattern

This lecture is a pure probability / estimation-theory problem wearing a linear-regression costume. You are not fitting a model here — you are asking a meta-question about a model you already fit: "If I reran this experiment with fresh noise, how much would my estimated weights wobble around the truth?"

The mental mode to switch into: ŴML is a random variable, not a fixed number. Every time you'd say "the estimate is X," you should mentally add "...for this particular noisy sample." That single reframing is 80% of this lecture.

Analogy Think of an archer shooting at a bullseye (the true W) in windy conditions (the noise ε). Each arrow (each ŴML) lands somewhere different because the wind changes shot to shot. "Goodness of the estimator" is not asking where one arrow landed — it's asking: on average, how far do arrows land from the bullseye, and can we tell from the archer's stance (the feature matrix X) whether the spread will be tight or wide?
0

The Problem

You've derived that ŴML = (XᵀX)-1XᵀY minimizes squared error and maximizes likelihood. Great — but that derivation only proves it's the best fit to the data you happened to observe. It says nothing about whether that fit is close to the actual physical/generative relationship W that produced the data.

Two datasets generated by the exact same true W, with different random noise draws, will produce two different ŴML's. So which one do you trust? This lecture gives you a number that answers: "on average, how far off is my estimator, and what controls that distance?"

Why this matters practically A model can have low training error and still have an unreliable ŴML — e.g. under multicollinearity. Training error alone won't warn you. This lecture's formula will.
1

History

This is a compressed stage — it builds directly on classical estimation theory rather than having a distinct invention story of its own.

Gauss and Legendre gave us least squares in the early 1800s purely as a curve-fitting trick — minimize sum of squared errors, done. It took the later development of probability theory (Fisher's formalization of Maximum Likelihood in the 1920s) to show that least-squares isn't an arbitrary choice: under Gaussian noise, it is the maximum likelihood estimator. Once that equivalence was established, statisticians immediately asked the natural follow-up — "how good is this estimator?" — which is exactly the question that led to variance/covariance analysis of ŴML, the subject of today.

2

Engineering Thinking

Before writing any math, whiteboard the requirements for a "goodness" measure of an estimator:

What we want

• A single scalar number summarizing how far ŴML typically lands from W.

• It should account for the fact that ŴML is random (average over all possible noise draws).

• It should penalize distance in any direction of the weight-vector space, not just one coordinate.

Constraints

• Must be computable from things we control or observe: X, and (if known/estimated) σ².

• Should decompose cleanly enough that we can see which factor (noise vs. features) is responsible for poor performance.

Formula Construction

We build the result piece by piece rather than dropping it fully formed. Start from the generative model:

Generative Model
Y = WTX + ε,   ε ∼ 𝒩(0, σ²)
Eq. 34.1
Xobserved feature matrix (n rows × d features)
Yobserved labels/targets
Wthe true, unknown weight vector
εGaussian noise, mean 0, variance σ²

We already derived (previous lectures) that the MLE solution equals the least-squares closed form:

MLE Solution (recall)
ŴML = (XTX)-1 XTY
Eq. 34.2

Substitute Eq. 34.1 into Eq. 34.2 — this is the key algebraic move that will let noise "fall out" cleanly:

Substitution
ŴML = (XTX)-1XT(XW + ε) = (XTX)-1(XTX)W + (XTX)-1XTε ŴML = W + (XTX)-1XTε
Eq. 34.3
The construction moment Look at Eq. 34.3: the estimate equals the truth plus a noise term. This single line is why the whole lecture works — it tells us the "error" of our estimator is literally just the noise, reshaped by (XᵀX)⁻¹Xᵀ. Now "how good is ŴML?" becomes "how big does noise get after this reshaping?" — a question we can answer with expectations.

Rearranging Eq. 34.3 gives the estimator's error directly, then we square, norm, and expect it — assembling the final formula:

Target Formula — Goodness of MLE
𝔼[‖ŴML − W‖²] = σ2 · Tr((XTX)-1)
Eq. 34.4 — the result

Plain English Expected squared error of the estimate = noise level × a number describing how "spread out / correlated" your features are. Two independent knobs, multiplied together.
6

Derivation

We pick up from Eq. 34.3: ŴML − W = (XᵀX)⁻¹Xᵀε. Let's push this all the way to Eq. 34.4.

1
Define the error vector
let  δ = ŴML − W = (XTX)-1XTε
δ is a linear transformation of the Gaussian noise vector ε — that's what makes it tractable.
2
Write squared norm as inner product
‖δ‖² = δTδ = εTX(XTX)-1(XTX)-1XTε
Transpose of a product reverses order: δᵀ = εᵀX(XᵀX)⁻¹ (since (XᵀX)⁻¹ is symmetric, its transpose equals itself).
3
Take expectation over ε
𝔼[‖δ‖²] = 𝔼[ εᵀ · A · ε ],   where A = X(XᵀX)⁻²Xᵀ
A quadratic form in a random vector — this is exactly the setup where the trace trick applies.
4
Apply the trace trick
𝔼[εᵀAε] = Tr(A · Cov(ε)) = σ² · Tr(A)
For zero-mean ε with covariance σ²I, 𝔼[εᵀAε] = σ²Tr(A) — a standard identity because a scalar equals its own trace, and trace is cyclic: Tr(εᵀAε)=Tr(Aεεᵀ), then 𝔼[εεᵀ]=σ²I.
5
Simplify the trace using cyclic property
Tr(X(XᵀX)⁻²Xᵀ) = Tr((XᵀX)⁻²·XᵀX) = Tr((XᵀX)⁻¹)
Cyclic permutation inside Tr(·) lets XᵀX and (XᵀX)⁻² collapse together, since (XᵀX)⁻²(XᵀX) = (XᵀX)⁻¹.
6
Final result
𝔼[‖ŴML − W‖²] = σ² · Tr((XᵀX)⁻¹)
Exactly Eq. 34.4. Noise variance and feature geometry appear as two clean, separable factors.
Numerical sanity check Suppose d = 1 (single feature), so XᵀX is just a scalar = Σxᵢ². Then the formula reduces to 𝔼[(ŵ − w)²] = σ²/Σxᵢ² — the familiar "variance of the slope estimate" from simple linear regression. This is a good self-check: the general matrix formula must collapse to the 1-D case you may already know.
7

Algorithm

This isn't a "training" algorithm — it's a diagnostic you run alongside training to audit reliability.

# Inputs: X (n x d design matrix), Y (n,), sigma2 (noise variance, known or estimated)

def estimator_quality(X, sigma2):
    XtX      = X.T @ X                    # d x d Gram matrix
    XtX_inv  = np.linalg.inv(XtX)      # (X^T X)^-1
    trace    = np.trace(XtX_inv)       # sum of diagonal entries
    expected_sq_error = sigma2 * trace
    return expected_sq_error

# Usage alongside fitting:
W_hat = XtX_inv @ X.T @ Y                 # the MLE / least-squares fit
quality = estimator_quality(X, sigma2_hat)

σ² itself isn't known in practice — it's usually estimated from residuals: σ̂² ≈ RSS / (n − d).

8

Optimization

Computational cost

Forming and inverting XᵀX is O(nd² + d³). For high-dimensional d, explicit inversion is avoided — use a Cholesky or QR decomposition of X and read the trace off the decomposition instead of computing a full inverse.

Trick

You rarely need the full matrix (XᵀX)⁻¹ — only its trace. If you already have the SVD X = UΣVᵀ, then Tr((XᵀX)⁻¹) = Σ 1/σᵢ² over the singular values σᵢ of X. Much cheaper and numerically stabler than a direct inverse.

9

Edge Cases

1. XᵀX is singular or near-singular (multicollinearity). If two features are highly correlated (or d > n), (XᵀX)⁻¹ blows up — some diagonal entries become huge, so Tr((XᵀX)⁻¹) → ∞. The formula is correctly telling you: the MLE exists but is essentially useless, wildly unstable across resamples.

2. d ≥ n (more features than samples). XᵀX isn't even invertible. ŴML is undefined without regularization (ridge, etc.) — the formula's assumptions break down entirely.

3. σ² unknown. In practice σ² is estimated from residuals; the formula then has extra estimation noise baked in via σ̂², which itself has some sampling variance — a second-order effect not covered by Eq. 34.4 directly.

Common misconception A small training/residual error does not imply small 𝔼[‖ŴML − W‖²]. You can fit the observed points almost perfectly while still being far from the true W, if the features are poorly conditioned. Residual error and estimator error measure different things.

Problem Families

Ridge Regression

Adds a penalty λ‖W‖² to trade a little bias for a large reduction in variance — directly motivated by this lecture's insight that Tr((XᵀX)⁻¹) can explode.

Cramér–Rao Lower Bound

States no unbiased estimator can beat Var ≥ (Fisher Information)⁻¹. For linear regression, ŴML actually achieves this bound — it's provably the best unbiased estimator (Gauss–Markov / efficiency).

Bias–Variance Decomposition

The general framework this result is a special case of: total error = bias² + variance (+ irreducible noise). Here bias is exactly zero, so all error is "variance."

Optimal Experimental Design

Explicitly chooses X (which inputs to measure at) to minimize Tr((XᵀX)⁻¹) subject to a measurement budget — a direct engineering application of today's formula.

Invariant Library ⭐

Always true

• ŴML is unbiased: 𝔼[ŴML] = W exactly (given the Gaussian linear model assumptions hold).

• 𝔼[‖ŴML − W‖²] scales linearly in σ².

• More/better-spread data (larger, more diverse XᵀX) can only shrink or keep equal — never increase — Tr((XᵀX)⁻¹), for a fixed feature set.

Sometimes true

• "Adding more features improves the estimator" — only if those features are genuinely informative and not collinear with existing ones. Adding a near-duplicate feature can inflate Tr((XᵀX)⁻¹) instead.

• "More data always reduces this error" — true in aggregate as n grows for i.i.d.-style designs, but a badly chosen new data point (near-collinear with old ones) can still leave Tr((XᵀX)⁻¹) nearly unchanged.

Never true

• ŴML is never guaranteed to equal W exactly for any single draw — only in expectation, not sample-by-sample. (Counterexample: run the fit twice on resampled noise, get two different answers — both "correct" MLEs.)

• Low residual/training error does not imply low 𝔼[‖ŴML−W‖²] — see edge case #1 above (multicollinearity can give perfect-looking fits with terrible parameter reliability).

17

Expert Thinking

A practitioner doesn't re-derive this every time — they just glance at two things: (a) the condition number of XᵀX (or equivalently, correlation among columns of X), and (b) the estimated residual variance σ̂². If condition number is huge, they know instantly, without computing anything further, that coefficients will be unstable — and reach straight for ridge regression, feature selection, or PCA-based dimensionality reduction before even looking at p-values.

The compressed intuition experts carry: "variance of my coefficients = noise × how badly my features overlap." Two words to listen for in your own head: collinearity and noise.

Examiner Trap Library ⭐

Q: "Since ŴML minimizes training error, it must also be the estimator with smallest 𝔼[‖Ŵ−W‖²] among all possible estimators." True or false?
✗ Tempting answer: "True — it's the optimal fit, so it must be optimal in every sense."
✓ Correct: True, but for a subtler reason — it's optimal specifically among unbiased estimators (Gauss–Markov / Cramér–Rao). A biased estimator (e.g. ridge) can have strictly lower 𝔼[‖Ŵ−W‖²] by trading a little bias for a lot less variance.
Q: "If I double the amount of training data (n), 𝔼[‖ŴML−W‖²] is guaranteed to halve." True or false?
✗ Tempting answer: "True — more data always means better estimates."
✓ Correct: Not guaranteed in general — it depends entirely on how the new points affect Tr((XᵀX)⁻¹). It's typically true for i.i.d.-style sampling, but not a mathematical certainty for arbitrary new points (e.g. duplicating an existing row changes nothing about which directions XᵀX is weak in).
Q: A student writes 𝔼[‖ŴML−W‖²] = σ² · (XᵀX)⁻¹ (dropping the trace). Why is this wrong?
✗ (XᵀX)⁻¹ is a d×d matrix — you cannot equate a scalar (expected squared norm) to a matrix.
✓ The trace is what collapses the matrix Cov(Ŵ)=σ²(XᵀX)⁻¹ down into the single scalar 𝔼[‖Ŵ−W‖²] = sum of per-coordinate variances = Tr(Cov(Ŵ)).

Exam Shortcuts

• See "expected squared error of an estimator" in a Gaussian-noise linear model → immediately write σ²Tr((XᵀX)⁻¹) without re-deriving, then adjust only if the question changes an assumption.

• To eliminate wrong MCQ options fast: any option that doesn't have σ² multiplied by something involving X is wrong (both factors must appear, separably).

• If asked for the 1-D / simple linear regression special case, remember the reduction: σ²/Σxᵢ² — a good way to sanity-check any general-d answer choice by setting d=1 mentally.

20

Industry Implementation

• statsmodels (`OLS(...).fit()`) — the `.bse` (standard errors) and full covariance matrix `.cov_params()` reported after fitting are literally σ̂²(XᵀX)⁻¹ under the hood; the diagonal gives per-coefficient variance, and its trace is exactly today's quantity.

• sklearn — `LinearRegression` doesn't report this by default (it's fit-focused, not inference-focused); you'd combine it with `statsmodels` or compute `np.linalg.inv(X.T@X)` yourself for this diagnostic.

• VIF (Variance Inflation Factor) — a standard collinearity diagnostic in most stats packages — is essentially a per-feature decomposition of exactly the same Tr((XᵀX)⁻¹) blow-up this lecture warns about.
