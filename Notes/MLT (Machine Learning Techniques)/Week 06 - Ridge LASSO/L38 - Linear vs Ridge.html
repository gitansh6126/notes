Linear Regression vs. Ridge Regression

Why does adding one penalty term to the loss function turn an unbounded search into a geometric collision between an ellipse and a circle? This lecture builds the picture that explains it.

Geometric Interpretation L2 Regularization Constrained Optimization Prelude to Lasso
0Problem

The gene-expression trap

Imagine you're predicting a patient's disease risk from 10,000 gene-expression features, but you only have 200 patients in your dataset. You run ordinary linear regression. It "works" — the training error is nearly zero. But the coefficient vector w is a mess: some weights are +40,000, others are −38,500, and a tiny change in one patient's data sends every coefficient swinging wildly.

The model hasn't learned biology. It has memorized noise, using huge opposing weights that cancel out on the training set but explode on any new patient. Standard linear regression has no mechanism to say "stop — those weights are unreasonably large, prefer smaller ones." It only cares about minimizing squared error, however extreme the coefficients need to be to get there.

⚠️
The core tensionA loss function that only rewards fitting the training data has no built-in preference for "reasonable" solutions over "extreme but technically lower-error" ones. We need a second force pulling weights back toward zero.
1History

Where the circle came from

The mathematical trick behind Ridge Regression — adding λ times a squared-norm penalty — predates machine learning entirely. Soviet mathematician Andrey Tikhonov introduced this kind of penalty in the 1940s–60s to stabilize ill-posed inverse problems (problems where tiny input changes cause huge, unstable output changes). It's still called Tikhonov regularization in numerical analysis.

Statisticians Arthur Hoerl and Robert Kennard brought the idea into regression in 1970, naming it "Ridge Regression" after the ridge-like shape the penalty term added to the diagonal of a matrix being inverted — directly fixing the numerical instability that appears when features are highly correlated (multicollinearity), which is exactly the gene-expression scenario above.

2Engineering

What a fix must satisfy — before any formula

Before writing math, an engineer lists requirements for a fix to the "extreme coefficients" problem:

Must discourage largeness

Any mechanism must actively penalize big weight values, not just leave them unconstrained.

Must stay differentiable

We still want to use calculus (gradients) to find the minimum — no jagged, non-smooth penalty.

Must not distort the loss shape too much

The penalty should gently compete with the error term, not dominate it — controllable by a single knob.

Must treat all coefficients symmetrically

No coordinate should be arbitrarily favored — the penalty should depend only on magnitude, not direction.

A candidate that fails: simply capping each weight at a hard threshold — not differentiable, arbitrary per-coordinate cutoffs, and clumsy to optimize. That candidate gets rejected before it's even written mathematically.

3Mathematical Translation

Turning requirements into symbols

Engineering requirementMathematical property
Discourage largenessAdd a term that grows as any wi grows
Stay differentiableUse a square, not an absolute value (|·| has a kink at 0)
Symmetric across coordinatesSum of squares over all coordinates — the squared L2 norm ‖w‖22
Controllable strengthMultiply by a tunable non-negative constant λ
💡
Why squares, not absolute values (yet)Squaring keeps the penalty smooth everywhere, including at zero — essential for using gradient-based calculus later. We'll see in the next lecture what happens when you deliberately give up that smoothness (Lasso).
4Formula Construction

Building both objectives, piece by piece

Piece 1 — Ordinary Linear Regression (the ML solution)

Squared error between prediction and truth, summed over every training point:

Linear Regression Loss
J(w)  =  Σi=1n (wTxi − yi)2
Eq. 38.1

No constraint on w — this is the Maximum Likelihood (ML) solution under a Gaussian-noise assumption, and we'll call its minimizer wML.

Piece 2 — Ridge Regression (add the penalty from Stage 3)

Ridge Regression Loss
J(w)  =  Σi=1n (wTxi − yi)2  +  λ‖w‖22
Eq. 38.2
w the coefficient vector being solved for
xi, yi the i-th feature vector and its true target
λ non-negative hyperparameter controlling penalty strength
‖w‖22 squared L2 norm = w12+w22+…

Every symbol, why it's there

🏋️
AnalogyThink of wML as the point an unsupervised athlete would sprint to for the fastest time (lowest error), with no rules. λ is a coach who says: "You may only move this far from the starting line." The athlete still tries to get as close as possible to the fast finish, but is physically restrained by a leash of length √Θ.
6Derivation — The Geometric Interpretation

Ridge Regression as a constrained optimization

Minimizing Eq. 38.2 directly (an unconstrained sum of two terms) is mathematically equivalent to solving a constrained version of Eq. 38.1: minimize the original error, but only search inside a bounded region.

Equivalent Constrained Form
minimize  J(w)    subject to    ‖w‖22 ≤ Θ
Eq. 38.3

Here Θ is a "budget" for total squared weight size — every valid choice of λ in Eq. 38.2 corresponds to some budget Θ in Eq. 38.3 (a larger λ means a smaller Θ, and vice versa). They're two ways of writing the same restriction.

Reading this in 2D

With just two weights w1, w2, we can literally draw both pieces of Eq. 38.3:

  • The constraint w1² + w2² ≤ Θ is a filled circle centered at the origin with radius √Θ — every point inside or on this circle is "allowed."
  • The loss function J(w) is a bowl-shaped (quadratic) surface in w-space. Its bird's-eye-view contour lines — points of equal error — are concentric ellipses centered exactly on the unconstrained optimum wML. The further out an ellipse, the higher its error.
The Ridge solution is the first point of contact between the growing ellipses (equal-error contours) and the fixed constraint circle.

The tangency argument

Start at the constrained region's cheapest possible point and imagine the ellipses expanding outward from wML like ripples (each ripple = a higher error level). The smallest ellipse that still touches the circle at all marks the lowest error achievable while staying inside the budget. That contact point — where an ellipse is tangent to the circle — is exactly wRidge.

The tangency point's coordinates are the Ridge solution.
📐
Why tangency, not intersectionIf an ellipse merely crossed the circle (two intersection points), you could always find a still-smaller ellipse that also touches the circle — so the true minimum-error point on the boundary is where the ellipse just grazes it: a single point of tangency.

At λ = 0, the circle is large enough to contain w_ML entirely — Ridge collapses to plain Linear Regression. As λ → ∞, the circle shrinks to a point at the origin, forcing w → 0.

7Algorithm

Turning the picture into a procedure

In practice you never draw circles and ellipses to solve Ridge Regression — a closed-form solution exists, extending linear regression's normal equation with a diagonal correction:

Closed-form Ridge Solution (extension beyond source notes)
wRidge  =  (XTX + λI)−1 XTy
Eq. 38.4

Compare to plain linear regression's normal equation, wML = (XTX)−1XTy — Ridge simply adds λI to the matrix before inverting it, which is also exactly the fix that makes the matrix invertible even when features are perfectly correlated (the original historical motivation from Stage 1).

# pseudocode — Ridge Regression, closed form
function ridge_fit(X, y, lam):
    n_features = X.shape[1]
    I = identity_matrix(n_features)
    # the "ridge" added to the diagonal — Hoerl & Kennard's original fix
    A = X.T @ X + lam * I
    w_ridge = inverse(A) @ X.T @ y
    return w_ridge
8Optimization — Choosing λ

The knob has to be tuned, not guessed

λ = 0 gives ordinary linear regression (no shrinkage, possible overfitting). λ → ∞ shrinks every weight to zero (a useless, underfit model that predicts the same value regardless of input). The right λ sits between these extremes, and in practice it's found the same way any hyperparameter is:

  • k-fold cross-validation: try a range of λ values, measure validation error for each, pick the λ with lowest validation error (not lowest training error — that would always favor λ = 0).
  • Regularization path: plot each coefficient's value as λ sweeps from 0 to large — watch coefficients shrink smoothly toward zero without any hitting exactly zero (this smooth shrinkage, never landing on zero, is the key visual signature of Ridge, revisited in Stage 9).
9Edge Cases

Where the picture bends

CaseWhat happens
λ = 0Θ → ∞, the circle grows to contain w_ML, tangency point = w_ML itself. Ridge reduces exactly to Linear Regression.
λ → ∞Θ → 0, the circle shrinks to a single point at the origin. Every coefficient is forced to zero regardless of the data.
Highly correlated features (multicollinearity)XTX becomes near-singular (hard to invert) — the historical problem Ridge was invented to fix; adding λI restores invertibility.
Features on very different scales‖w‖² penalizes large-scale-feature weights unfairly more; features must be standardized before applying Ridge.
10Pattern Recognition

Signals that should make you reach for Ridge

Many more features than data points Coefficients wildly unstable across resamples Highly correlated predictors Training error ≈ 0, validation error high You want to keep all features, just shrink them

If you instead see a hint like "most features are probably irrelevant and should be dropped entirely", that's a different signal — pointing toward Lasso (Stage 12), not Ridge.

11Formula Shape Recognition

Same shape, different names

Learn to spot the pattern "loss + λ·(something squared)" under whatever notation a course or paper uses:

Field / ContextNotation

Numerical analysis (Tikhonov)‖Ax − b‖² + α‖Γx‖²

Bayesian viewEquivalent to placing a Gaussian prior on w — the penalty is the negative log of that prior
12Problem Families

Ridge's siblings: the regularization family

Ridge (L2)

Penalty ‖w‖₂². Constraint region is a circle/sphere. Shrinks coefficients smoothly; never exactly zero.

Lasso (L1) — next lecture

Penalty ‖w‖₁ (sum of absolute values). Constraint region is a diamond with sharp corners on the axes — tangency often lands exactly on a corner, forcing some weights to exactly zero → automatic feature selection.

Elastic Net

A weighted mix of both penalties — combines Ridge's stability with Lasso's sparsity.

Early stopping / weight decay (deep learning)

Different mechanisms, same goal: keep parameters from growing unnecessarily large.

13Expert Thinking

How a practitioner actually thinks about this

🧠
Mental shortcut"Circle → smooth shrink, never zero. Diamond → corners, some weights die." A practitioner doesn't re-derive the geometry each time; they recall this one-line rule to instantly predict whether a regularizer will produce sparsity.
🧠
Mental shortcutBigger λ is never "better" in an absolute sense — it trades variance for bias. An expert always asks "shrink relative to what validation curve?" rather than picking a large λ on principle.
14Exam Shortcuts

IITM-style traps and fast checks

🎯
Common trap question"Does Ridge Regression set coefficients to exactly zero?" — No. The constraint region (a smooth circle/sphere) has no corners, so the tangency point almost never lands exactly on an axis. Students who confuse Ridge with Lasso answer "yes" and lose the mark.
🎯
Fast sanity checkIf a question describes a diamond-shaped constraint region → it's Lasso. Circle/sphere → it's Ridge. This single visual cue answers most MCQs on this topic instantly.
🎯
ShortcutRemember direction of the λ-Θ relationship: λ ↑ ⟹ Θ ↓ ⟹ circle shrinks ⟹ coefficients shrink. Don't get the direction backwards under time pressure.

Common Mistakes

✗"Ridge Regression performs feature selection."
✓Ridge shrinks coefficients toward zero but essentially never sets them exactly to zero — no feature selection. That's Lasso's job.
✗Forgetting to standardize features before Ridge.
✓‖w‖² penalizes raw coefficient magnitude — features on larger scales get artificially smaller coefficients even if equally important, so standardize first.
✗Choosing λ by minimizing training error.
✓Training error is minimized at λ = 0 by definition — always tune λ using validation/cross-validation error instead.
15Industry Implementation

What this looks like in real tools

# scikit-learn
from sklearn.linear_model import Ridge

model = Ridge(alpha=1.0)  # alpha == λ in sklearn's naming
model.fit(X_train, y_train)

Note the naming difference: scikit-learn calls the penalty strength alpha, not lambda (since lambda is a reserved keyword in Python). In deep learning frameworks, the same mechanism appears as the weight_decay parameter of an optimizer (e.g. PyTorch's torch.optim.SGD(..., weight_decay=λ)) — mathematically the identical L2 penalty, applied to neural network weights instead of linear regression coefficients.

16Connections

Where this leads next

This lecture set up the essential vocabulary — constrained optimization, tangency, the geometry of a penalty term — needed to understand the very next idea in the course: swap the circle for a diamond (L1 instead of L2), and suddenly the tangency point tends to land exactly on a corner of the diamond, driving some coefficients to exactly zero. That's Lasso Regression, and it turns regularization from "shrink everything a little" into "automatically decide which features to keep at all."

🔗
Thread forwardRidge answered "how do we keep coefficients small?" The unresolved question this lecture leaves open — restated in the source notes' own key takeaway — is: "it remains ambiguous whether to keep or discard certain features." That ambiguity is precisely Lasso's opening move.
