Lecture 37 · Regularized Regression

Ridge Regression

When several different weight vectors fit your data equally well, plain least squares has no way to choose between them. Ridge Regression breaks the tie — by preferring the smallest, most stable set of coefficients.

Cognitive Pattern

what kind of thinking is this?

🔷 Linear Algebra

Redundant features mean XXᵀ is singular or near-singular — there's an entire subspace of weight vectors that fit equally well.

⚙️ Optimization / Tie-Breaking

Among infinitely many zero-error solutions, we need a secondary criterion to pick one — smallest norm.

🎲 Probability

The same tie-breaker falls out naturally if you believe, a priori, that weights are more likely to be small (Bayesian view, Lecture 38).

0

The Problem

Why does this problem exist?

Standard linear regression finds ŵML = argminw Σ(wTxi − yi)². This works fine when features are independent. But add a redundant feature — one that's a linear combination of others (e.g. a "BMI-like" feature built from Height and Weight) — and suddenly many different weight vectors produce the exact same predictions and the exact same loss. The loss function alone can't tell them apart.

⚠️
What happens if we don't solve it? The specific weights returned become arbitrary — sensitive to tiny numerical noise, hard to interpret, and unstable: retrain on a slightly different sample and the coefficients can swing wildly, even though predictions stay identical.
📏
Real-life analogy. If two rulers always agree — one measures in inches, the other in a fixed multiple of inches — then "how much of the length was measured by ruler A vs ruler B" is a meaningless question; infinitely many splits explain the same total length. Ridge Regression is the rule "when in doubt, split it as evenly/minimally as possible" rather than letting the split be arbitrary.
1

History

Ridge Regression was formalized by Hoerl & Kennard (1970) precisely to handle multicollinearity — the statistical name for feature redundancy. It's the same estimator derived two other ways in this course: as a fix for exploding MSE via eigenvalue shrinkage (Lecture 35), and as the MAP estimate under a Gaussian prior (Lecture 38). This lecture arrives at it from a third angle — as a principled tie-breaker among equally-good solutions.

Engineering Thinking

before any math

Property we want

Among all weight vectors achieving (near-)minimum training loss, pick the one that is simplest — smallest magnitude.

Constraint

Can't just discard the redundant feature (we may not know in advance which features are redundant, or by how much) — the fix must work automatically, for any dataset.

💡
Engineering instinct: add a second, small cost to the objective that only cares about the size of w — this nudges the optimizer toward the smallest-norm member of the tied solution set, without needing to know which features are redundant ahead of time.

Derivation — Worked Example: Redundant Features

Setup

Three features: Height (h), Weight (m), and a redundant third feature r = 2h + 3m. Suppose the true target is y = h + m. Any weight vector of the form below fits the data perfectly (zero training loss), for any value of t:

Family of perfect-fit solutions
wh=1−2t    wm=1−3t    wr=t
for any t ∈ ℝ

Check: t·r + (1−2t)h + (1−3t)m = t(2h+3m) + h−2th + m−3tm = h + m ✓ — the t-terms always cancel, so every t gives exactly zero error.

🎲
Plain least squares is indifferent between t=0 (weights 1, 1, 0 — ignore the redundant feature entirely) and t=1 (weights −1, −2, 1 — lean entirely on the redundant feature) and every value in between. Nothing in the loss function prefers one over another.
📐
Ridge breaks the tie by minimizing ‖w‖² = (1−2t)² + (1−3t)² + t² over t — picking the smallest vector from the whole tied family.

Takeaway: as λ→0⁺, Ridge converges exactly to this minimum-norm tie-breaker (t*=5/14 here). For λ>0, Ridge goes one step further: it also shrinks the overall solution slightly toward zero, trading a small amount of training fit for even more stability — the same fit-vs-size tradeoff seen in Lecture 35 and Lecture 38, just motivated here by redundancy rather than eigenvalues or priors.

Algorithm

# pseudocode: fit Ridge Regression
def fit_ridge(X, Y, lam):
    d = X.shape[0]                      # number of features
    A = X @ X.T + lam * np.eye(d)
    w_ridge = np.linalg.solve(A, X @ Y)   # solve, don't explicitly invert
    return w_ridge

# lambda chosen via K-fold CV, same recipe as Lecture 35
🛠️
In practice, always standardize features first (zero mean, unit variance) — the penalty λ‖w‖² treats every coefficient equally, so features on different scales would be penalized unfairly otherwise.

Edge Cases & Limitations

λ = 0

Falls back to plain least squares — tie-breaking disappears, arbitrary solution among the tied family returned (numerically, whichever the solver happens to land on).

λ too large

All coefficients shrink toward 0 — even genuinely useful (non-redundant) features get suppressed, hurting fit.

Unscaled features

A feature measured in millimeters gets penalized far more harshly than the same feature in meters — always standardize first.

Doesn't do feature selection

Ridge shrinks the redundant feature's weight but rarely to exactly zero — if you want it eliminated entirely, that's Lasso's job (L1), not Ridge's (L2).

Pattern Recognition

when to reach for this
  • You have engineered features that are combinations of others (ratios, sums, interaction terms).
  • Coefficients change drastically between re-training runs on similar data.
  • p (features) is close to or exceeds n (samples).
  • You want to keep all features in the model but shrink the unreliable ones — as opposed to eliminating them (which is Lasso's job).

Problem Families

Ridge (L2)

Shrinks all weights smoothly, keeps every feature. Best when features are correlated but all plausibly relevant.

Lasso (L1)

Drives redundant/irrelevant weights to exactly zero — true feature selection.

Elastic Net

Mix of both — handles groups of correlated redundant features better than pure Lasso.

16

Invariant Library ⭐

Always True

Among all exact-fit solutions to an underdetermined system, there is a unique minimum-norm one — and it's what λ→0⁺ Ridge converges to.

Sometimes True

"Ridge sets redundant weights to zero" — only approximately; L2 shrinks but essentially never zeroes out exactly.

Never True

Ridge never changes predictions on the training data when λ=0 vs. any other tied minimizer — all members of the tied family give identical fitted values on training data.

Expert Thinking

🧠
An expert who sees a correlation matrix with near-1.0 off-diagonal entries doesn't panic about which feature is "the real one" — they immediately reach for Ridge, knowing it will automatically spread credit sensibly across the redundant group rather than arbitrarily dumping it all on one.
18

Examiner Trap Library ⭐

🪤
Trap 1: "Redundant features cause higher training loss" — false. Training loss can still hit zero; the problem is the coefficients become ill-defined/unstable, not the fit quality.
🪤
Trap 2: Thinking Ridge "removes" redundant features — it shrinks, it doesn't eliminate (that's Lasso).
🪤
Trap 3: Forgetting to standardize features before applying Ridge — unscaled features get unevenly penalized, biasing which "tied" solution gets picked.
🪤
Trap 4: Assuming λ only affects redundant/correlated coefficients — it penalizes every weight, including well-identified, non-redundant ones, just typically with less visible effect.
19

Exam Shortcuts

  • "Multiple weight vectors give same loss" in a question → immediately think redundant/collinear features → Ridge as tie-breaker.
  • To find the minimum-norm member of a tied family: parameterize the family by one free variable t, minimize ‖w(t)‖² via calculus (a simple quadratic in t).
  • Asked "what does Ridge converge to as λ→0⁺ under redundancy?" → the minimum-norm exact-fit solution, not necessarily "the" original ground-truth weights.
  • Ridge formula is always ŵ = (XXᵀ+λI)⁻¹XY — memorize once, recognize under three names (Lec 35, 37, 38).

Industry Implementation

# scikit-learn: Ridge with standardization pipeline
from sklearn.linear_model import Ridge
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

model = make_pipeline(StandardScaler(), Ridge(alpha=1.0))
model.fit(X_train, y_train)

# inspect shrinkage on a redundant-feature dataset
print("coefficients:", model.named_steps['ridge'].coef_)
🛠️
Check VarianceInflationFactor (VIF) from statsmodels beforehand to actually detect which features are redundant — Ridge treats the symptom, VIF diagnoses the cause.

One-Page Brain ⭐

Core Intuition

  • Redundant features create a whole family of weight vectors with identical (often zero) training loss. Ridge's L2 penalty breaks the tie by selecting the smallest-norm member of that family, and further shrinks it as λ grows — trading a little fit for a lot of stability.

5 Formulas

  • OLS: argmin Σ(wᵀxᵢ−yᵢ)²
  • Ridge: argmin Σ(wᵀxᵢ−yᵢ)² + λ‖w‖²
  • Stationary point: XXᵀw − XY + λw = 0
  • ŵ_R = (XXᵀ + λI)⁻¹XY
  • Worked example: ‖w(t)‖² = 2 − 10t + 14t², minimized at t*=5/14
