Inside the Decision Tree Algorithm

Lecture 43 defined entropy and information gain. This lecture asks the practical question: how does the algorithm actually turn a spreadsheet of real numbers into that tidy little checklist?

◆ Axis-Parallel Geometry ◆ Search over Thresholds ◆ Bias–Variance Tradeoff
1

Feature Discretization

where do candidate questions come from?
📏
Lecture 43 assumed a question like "Sports Interest ≤ 6?" just appeared out of nowhere. It doesn't. Sports Interest is really a continuous score from 0 to 10 — the algorithm has to invent that threshold of 6 itself, by trying a spread of candidate cut points.

For each continuous feature, the range from its minimum to its maximum observed value is sliced into a fixed number of partitions — commonly around 10. Every partition boundary becomes one candidate question. Information Gain (Lecture 43) is computed for every candidate across every feature, and the single best one is chosen.

FIG. 1 — every gray dot is one candidate question tested; the gold dot wins the Information Gain comparison from Lecture 43.
Practical note More partitions mean finer, potentially better thresholds — but also more Information Gain calculations per node. Ten is a common default balance between resolution and speed; it isn't a fixed law.
2

Recursive Splitting

the same trick, applied again and again

Once the root question is chosen, the two resulting groups — D_Yes and D_No — are each treated as a brand-new, smaller dataset. The exact same procedure (discretize → score every candidate → pick the best) runs again, independently, inside each group. This is what makes the algorithm recursive: the whole tree is built from one repeated rule, applied at every node.

As splits accumulate, some later candidate questions become redundant — for instance, re-testing "Sports Interest ≤ 6?" inside a branch that already only contains students with Sports Interest ≤ 6 can no longer separate anyone. These redundant questions contribute zero Information Gain and are naturally skipped.

3

Depth — The Hyperparameter

the tree's version of K

Just as Lecture 42's K controlled how "rugged" a KNN boundary could get, tree depth — the longest root-to-leaf path — controls how complex a tree is allowed to become. It is chosen, not learned.

Stopping early — purity thresholds

A node can stop splitting once it's "pure enough" — commonly once more than 90% (or fewer than 10%) of its labels belong to one class, even if it isn't perfectly pure.

The extreme case

If nothing stops it, a tree can keep splitting until every leaf holds exactly one training point. Training accuracy hits 100% — but the tree has simply memorised the dataset, one student at a time.

Overfitting, concretely A fully-grown tree that isolates every single training point is the tree equivalent of KNN's K = 1: perfect on data it has already seen, and needlessly fragile on anything new.
Tuning depth Exactly like K, depth is tuned by trying several values and checking each against a held-out validation set via cross-validation — keeping whichever depth maximises validation accuracy, not training accuracy.
4

Impurity Measures, Revisited

entropy isn't the only option

Lecture 43 built Entropy from information theory — zero at pure nodes, peaking at a 50/50 split. The Gini Index is the other widely-used impurity measure, shaped the same way (0 at the extremes, maximum at p = 0.5) but computed without a logarithm, which makes it slightly cheaper to evaluate at every candidate threshold. In practice, both measures tend to select very similar splits.

5

Decision Boundaries — Axis-Parallel Splits

why trees draw rectangles, not curves

Every question in a tree compares one feature to one threshold — geometrically, that's a straight line running parallel to that feature's axis. Stack enough of these lines and the tree partitions the whole space into rectangles.

FIG. 3 — same idea of "separating two classes," two entirely different geometries.
Why this matters A pattern that genuinely requires a diagonal or curved boundary needs a decision tree to approximate it with many small rectangular steps — sometimes far more splits than the underlying pattern would seem to require.
6

Interpretability

the tree's biggest practical selling point

Once trained, a tree's prediction can always be explained as a short, plain-language chain: "predicted Football because Sports Interest > 6." This matters enormously outside the classroom — a doctor, loan officer, or judge can be shown the exact rule path behind a decision, something a KNN vote or a dense neural network usually cannot offer nearly as directly.

Quick Recall

the whole lecture in one glance

Continuous features get discretized into candidate thresholds; the algorithm greedily picks whichever candidate gives the highest Information Gain, then recurses on each resulting subset. Growth stops via a purity threshold or a maximum depth, tuned by cross-validation to avoid overfitting. The result is a set of axis-parallel, rectangular decision regions that are easy for a human to read.

Where This Leads

end of non-probabilistic classification

KNN and Decision Trees both classify using geometry and counting — distances, votes, splits — with no assumption about how the data was generated in the first place. The next lecture turns that around: by assuming a probabilistic story for how each class produces its data, we can build classifiers that reason in terms of likelihood rather than proximity or purity — the start of probabilistic modelling.
