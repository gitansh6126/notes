Layer 5 · Recognition

2. The Two Ways to Be Wrong

Every mistake the Perceptron can make falls into exactly one of two symmetric cases. Naming both explicitly makes the update rule's direction obvious rather than mysterious.

Mistake Type 1 — False Positive

Predicted +1 (since wₜᵀxᵢ ≥ 0) but the true label is −1.

wt+1 = wt − xi

The dot product wₜ₊₁ᵀxᵢ moves down — pulled toward and past zero, correcting toward the negative side.

Mistake Type 2 — False Negative

Predicted −1 (since wₜᵀxᵢ < 0) but the true label is +1.

wt+1 = wt + xi

The dot product wₜ₊₁ᵀxᵢ moves up — pulled toward and past zero, correcting toward the positive side.

TypePredictedTrue labelUpdateEffect on wᵀxᵢ
1+1−1w ← w − xᵢdecreases
2−1+1w ← w + xᵢincreases
🎯 Analogy — Whack-a-Mole
Here's the catch the lecture is building toward: fixing the mole in front of you (the current mistake) can pop up a different mole somewhere else (a point that used to be correctly classified). The update rule is provably correct for the specific point it just looked at — but it has zero memory of, or promise to, every other point on the board. That's the "local, not global" warning at the heart of this lecture.
🔑 Key Insight
The update is a strictly local correction — it guarantees the mistaken point is fixed right now, but makes no promise that previously-correct points stay correct. In principle, the algorithm could oscillate forever, fixing one point while breaking another.
Layer 4 · Reliability

3. The Failure Case: When "Separable" Isn't Enough

It's tempting to assume: "the data is linearly separable, so the Perceptron must eventually converge." Lecture 53's central twist is a counter-example that breaks this intuition — a small dataset (two points labeled +1, one labeled −1) where the algorithm can cycle between weight vectors, never settling on one that classifies everything correctly.

Fig 53.1 — Points sitting on/very near w^Tx=0 can make corrections chase each other in a loop
⚠️ Why This Happens
When a point lies on or extremely close to the current decision boundary, fixing it barely moves the boundary — just enough to flip that one point, but also just enough to flip a neighboring point onto the wrong side. With three tightly-packed points like this, the algorithm can be shown to revisit the same sequence of weight vectors indefinitely: linear separability was satisfied, yet convergence still failed.
Layer 2 · Derivation / Definition

4. The Fix: Linear Separability with a γ-Margin

The failure case above only arises because points are allowed to sit arbitrarily close to the boundary. The fix is to explicitly forbid that — require every point to be at least a fixed distance away from every valid separator, not just barely on the correct side of one.

γ-Margin Separability
∃ w* such that, ∀ (xi, yi): yi (w*)Txi ≥ γ
Eq. 53.2
w* some fixed separating weight vector (may not be unique)
γ > 0 a strictly positive constant — the guaranteed minimum "safety gap"
yᵢ(w*)ᵀxᵢ a signed margin — how far and on which correct side point i sits
Fig 53.2 — A guaranteed empty strip of width 2γ around the boundary — no point may sit inside it
💡 Reading the Definition
Plain-separability only says "every point is on its correct side" — a point can be a hair's width from the line and it still counts. γ-margin separability says "every point is on its correct side by at least γ" — the closest point to the boundary, over the best possible w*, still keeps a guaranteed clearance. This single strengthening is exactly what rules out the cycling counter-example from Section 3: no point can crowd the boundary anymore.
✅ Conclusion (this lecture)
Under γ-margin separability, the corner cases where the Perceptron fails to converge are ruled out by construction — every point keeps a guaranteed distance from any valid separator, so the earlier cycling scenario simply cannot occur. This is the assumption the rigorous convergence proof is built on.
📚 Beyond This Lecture — The Convergence Bound
The classical result built on this assumption (the Novikoff / Perceptron Convergence Theorem) goes one step further: if the data is γ-margin separable and every ‖xᵢ‖ ≤ R, the number of mistakes the Perceptron ever makes is bounded by R² / γ² — a finite number fixed in advance, regardless of the order points are presented in. Bigger margin ⇒ fewer mistakes needed; smaller margin ⇒ convergence is guaranteed but can take far longer. This bound isn't spelled out in today's slides but is the natural next fact once γ-margin separability is on the table.

Assumption & Invariant Library

AssumptionConsequence if violated
Plain linear separability onlyConvergence is not guaranteed — cycling is possible if points crowd the boundary
γ-margin separability (γ>0 fixed)Convergence is guaranteed, in at most R²/γ² updates
Bounded feature norms ‖xᵢ‖ ≤ RNeeded for the mistake bound to be finite and meaningful
  • Always true: a single update strictly corrects the specific mistaken point's score in the right direction.
  • Sometimes true: that same update leaves other points still correctly classified — not guaranteed, just common in practice.
  • Never true: plain linear separability (without a margin) guarantees termination in general.
⚠️ IITM Exam Trap
"Linearly separable" and "linearly separable with a γ-margin" are not the same assumption on an exam. If a question only states plain separability, you cannot cite the finite-mistake-bound theorem — that requires the strictly stronger γ-margin condition.
Layer 7 · Transfer

Connections & What's Next

This lecture reveals a pattern that recurs throughout ML theory: a clean, intuitive assumption ("the classes don't overlap") often needs to be strengthened with a quantitative safety margin before you can prove anything rigorous about an algorithm's behavior. You'll see the exact same move again, more explicitly, when Support Vector Machines make margin maximization the entire objective rather than an afterthought — SVM doesn't just require some margin to exist, it actively searches for the largest one possible.

Layer 7 · Retrieval Practice

Test Yourself

Why doesn't correcting one mistake guarantee the algorithm is closer to a global solution?
Show answer
The update is a local fix — it provably corrects the score for the specific point just examined, but makes no promise about points that were previously classified correctly; those can become mistakes as a side effect.
What property of the failure-case points causes the cycling behavior?
Show answer
The points sit on or extremely close to the current decision boundary, so small corrective updates flip one point onto the correct side while flipping another onto the wrong side, repeating in a loop.
How does γ-margin separability differ from plain linear separability?
Show answer
Plain separability only requires every point to be on the correct side of some hyperplane. γ-margin separability requires every point to be on the correct side by at least a fixed positive distance γ, ruling out points arbitrarily close to the boundary.

Perceptron Convergence — Everything on One Page

Core idea: the update rule locally fixes one mistake at a time, but with no safety margin between classes, corrections can chase each other forever even on separable data — the fix is to require a guaranteed gap γ.

  • Update: w ← w + yᵢxᵢ, applied only on mistakes
  • Mistake Type 1 (predicted +1, true −1): w ← w − xᵢ, score decreases
  • Mistake Type 2 (predicted −1, true +1): w ← w + xᵢ, score increases
  • Key insight: updates are local — fixing one point can break another
  • Failure case: points crowding the boundary can make the algorithm cycle, even though the data is linearly separable
  • Fix: γ-margin separability — ∃ w* such that yᵢ(w*)ᵀxᵢ ≥ γ > 0 for all i
  • Payoff: under γ-margin separability, convergence is guaranteed (extension: in at most R²/γ² mistakes)
