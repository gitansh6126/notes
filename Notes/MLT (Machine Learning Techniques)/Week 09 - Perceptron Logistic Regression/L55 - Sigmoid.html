The Sigmoid Function & the birth of Logistic Regression

The perceptron draws a hard line and refuses to say how sure it is. This lecture asks a simple but powerful question: what if a classifier could whisper a probability instead of shouting a verdict? The answer is the S-shaped curve that quietly powers half of modern machine learning.

Layer 1 — Understanding

The problem with a classifier that only shouts

Why the perceptron's confidence is exactly zero shades of grey.

⚖️
Analogy — the strict judge

Imagine a judge who only ever says "guilty" or "innocent" — never "probably guilty" or "70% sure." Even when the evidence is razor-thin and the case borderline, the verdict is delivered with the same absolute confidence as an open-and-shut case. That's the perceptron: P(y=1|x) is always exactly 1 or exactly 0, never 0.52.

Two concrete failures

1 · Linear inseparability

If even one red point and one blue point sit on the "wrong" side of every possible line, the perceptron's update rule never converges — it oscillates forever, hunting for a boundary that does not exist.

2 · No notion of confidence

A point 0.01 units from the boundary and a point 100 units from it get the identical prediction. The model cannot distinguish "barely positive" from "overwhelmingly positive."

Engineering thinking: reframe the goal

Instead of asking "which side of the line is x on?" — a question with only two possible answers — we ask "how far is x from the line, and can that distance be turned into a probability?" This single reframe is what unlocks everything else in the lecture. The linear score z = wTx doesn't disappear — the perceptron already computed it and threw away all but its sign. We keep the whole real number.

Mathematical Translation

Layer 2 — Derivation

Building the sigmoid from first principles

We don't pull the formula out of a hat — we derive it from three properties we demand of any "link function" G that turns a score into a probability.

Formula construction — three demands on G(z)

Boundary condition

G(0) = 0.5 — sitting exactly on the decision boundary should mean a coin-flip, 50/50 probability.

Upper bound

G(z) → 1 as z → +∞ — an overwhelmingly positive score should mean near-certainty of class +1.

Lower bound

G(z) → 0 as z → −∞ — an overwhelmingly negative score should mean near-certainty of class −1.

💡
Why not just clip the score?

A tempting shortcut: squash z by clipping it to [0,1] directly (e.g. max(0, min(1, z))). This satisfies all three conditions! But it is not smooth — it has sharp corners with zero gradient almost everywhere, which will matter enormously once we try to optimize w with calculus. We want a function that is smooth everywhere and whose derivative has a clean form.

A natural route: odds and log-odds

Statisticians already had a smooth, symmetric way to turn a bounded probability into an unbounded number: the log-odds (logit). We simply run that transformation backwards.

1
Start from odds
odds = P1 − P

Odds range from 0 (impossible) to +∞ (certain) — already unbounded on one side.

2
Take the log to unbound both sides
z = log P1 − P

Now z ranges over all of (−∞, +∞) exactly like our score wTx. We declare these equal — the log-odds IS the score.

3
Solve for P — invert the relationship
ez = P1 − P  ⟹  P = ez(1 − P)

Multiply both sides by (1 − P) and expand.

4
Isolate P
P(1 + ez) = ez  ⟹  P = ez1 + ez

Divide the numerator and denominator by e^z to get the familiar form below.

5
The sigmoid falls out
P = 11 + e−z = σ(z)

We didn't guess the S-curve — it is forced by demanding a smooth, symmetric map between an unbounded score and a bounded probability.

The Sigmoid (Logistic) Function
G(z) = 11 + e−z
Eq. 2.1
z the score wTx, any real number

🔢
Worked numerical example

Say a spam filter computes z = wTx = 1.5 for an email. Then G(1.5) = 1 / (1 + e−1.5) = 1 / (1 + 0.223) ≈ 0.817. The model doesn't just say "spam" — it says "about 82% likely to be spam," which a downstream system can threshold, rank, or combine with other signals.

Layer 3 — Computation

Turning the formula into an algorithm

From equation to code, with an eye on cost and numerical safety.

predict_proba.pyO(d) per example
import numpy as np

def sigmoid(z):
    # numerically stable: avoids overflow for very negative z
    return np.where(
        z >= 0,
        1 / (1 + np.exp(-z)),
        np.exp(z) / (1 + np.exp(z))
    )

def predict_proba(w, x):
    z = np.dot(w, x)          # O(d) — d = number of features
    return sigmoid(z)          # O(1) — one exponential

Time complexity

Computing z = wTx is a dot product over d features: O(d). Applying the sigmoid is a single exponential: O(1). Per-example inference is dominated entirely by the dot product.

Memory

Only the weight vector w ∈ ℝd needs to be stored — O(d) memory, independent of dataset size. This is why logistic regression scales to huge datasets: training data isn't kept around at inference time.

⚠️
Optimization trap: naive overflow

A literal translation of 1/(1+e−z) computes exp(-z) directly. For a very negative z (say −1000), exp(1000) overflows a float and returns inf, corrupting the result. The stable version above branches on the sign of z so the exponent argument is always ≤ 0, which never overflows — a small trick with big consequences at scale.

Layer 4 — Reliability

When does this model hold up?

Every model is a story about assumptions. Know them, and you know exactly where the story breaks.

Assumption library

AssumptionWhat it meansConsequence if violated
Log-odds are linear in xlog(P/(1−P)) = wTxA truly curved boundary is fit poorly; consider polynomial features or kernels
Observations are independentEach (x, y) pair is an independent coin tossCorrelated data (time series, repeated subjects) inflates confidence artificially
No perfect separationSome overlap between classes existsIf data IS perfectly separable, MLE pushes ‖w‖ → ∞ and never converges

Failure visualization — works → degrades → fails

Works

Score z near 0: the sigmoid has its steepest slope here, so small changes in x produce meaningfully different probabilities. This is where the model is most informative.

Degrades

|z| grows large: the curve flattens (saturates). A point with z = 8 and one with z = 20 are both ≈ 99.97% — the model becomes overconfident and stops distinguishing "sure" from "very sure."

Fails

Perfectly separable data: MLE keeps growing ‖w‖ forever to push every point's z toward ±∞, chasing a probability of exactly 1. The optimization never converges without regularization.

Invariants

ALWAYS: G(z) ∈ (0, 1), never exactly 0 or 1 ALWAYS: G(0) = 0.5 exactly ALWAYS: G(−z) = 1 − G(z), symmetric about z=0
SOMETIMES: decision boundary matches perceptron's if threshold = 0.5 SOMETIMES: probabilities are well-calibrated (only if model is correctly specified)
NEVER: G(z) reaches exactly 0 or 1 for finite z NEVER: gradient of G(z) is negative — it's monotonically increasing everywhere
Layer 5 — Recognition

Spotting this pattern in the wild

How to recognize when a problem — or a formula — is secretly asking for a sigmoid.

Hidden trigger phrases

"Probability of belonging to a class," "confidence score," "binary outcome with uncertainty," "convert a score to [0,1]" — all of these are asking for a link function like the sigmoid.

Formula shape recognition

Any expression of the form 1/(1 + e−something) — regardless of what "something" is — is a sigmoid in disguise, including logistic growth curves in biology and economics.

Symbol translation

You'll see this written as σ(z), G(z), logistic(z), or expit(z) across different textbooks — all identical formulas, different naming conventions.

Reverse engineering

If you're handed an S-shaped curve bounded in (0,1), symmetric around its midpoint, with a single steepness parameter — you're almost certainly looking at a sigmoid, even before seeing the formula.

Layer 6 — Engineering Judgment

Should you actually reach for this?

A formula is only as good as the judgment behind using it.

Do you need a probability, not just a class label?
No
Perceptron or hard-margin SVM may be simpler and faster to train
Yes
Continue — probabilistic model needed
Is the true decision boundary roughly linear in your features?
No
Use kernelized logistic regression, or a tree/neural model instead
Yes
Logistic regression with sigmoid is a strong, interpretable default
🚫
Why NOT to use it

Skip the sigmoid link when: (1) classes are perfectly separable and you have no regularization plan — training won't converge cleanly; (2) the relationship between features and log-odds is strongly non-linear and you can't or won't engineer features to fix it; (3) you need calibrated multi-class probabilities that sum to 1 across many classes — that's a job for softmax, sigmoid's multi-class generalization, not several independent sigmoids.

Generalization layer

The deep principle isn't "the sigmoid formula" — it's "pick a smooth, monotonic link function that maps an unbounded score to a bounded, meaningful quantity." Softmax generalizes this to many classes, the tanh function is a rescaled sigmoid used inside RNNs, and the same odds-based reasoning underlies logit models throughout statistics and econometrics.

Layer 8 — Research & Synthesis

Extensions and the complete cheat sheet

Open questions, and everything above compressed onto one page.

Calibration research

Modern deep networks using sigmoid/softmax outputs are often overconfident — the raw probability doesn't match true frequency. Techniques like temperature scaling and Platt scaling exist to recalibrate these outputs.

Vanishing gradients

Because the sigmoid saturates for large |z|, its derivative approaches zero — a core reason deep networks moved toward ReLU-family activations for hidden layers, reserving sigmoid mainly for output/gating roles.

🧠 One-Page Brain — Sigmoid & Logistic Regression

Core formula

G(z) = 1 / (1 + e−z), where z = wTx

Intuition

Turns a "how far from the boundary" score into a "how sure am I" probability.

Three defining properties
  • G(0) = 0.5
  • G(z) → 1 as z → ∞
  • G(z) → 0 as z → −∞
Key assumptions
  • Linear log-odds
  • Independent observations
  • No perfect separation
Common pitfalls
  • Overflow from naive exp(−z)
  • Non-convergence on separable data
  • Confusing sigmoid (binary) with softmax (multi-class)
Fitting w

Maximum Likelihood Estimation — find w that makes the observed labels most probable under the model.

Retrieval practice

Why must the link function satisfy G(0) = 0.5?
Because z = 0 means the point sits exactly on the decision boundary — equally consistent with either class — so the model should express total uncertainty: a 50/50 probability.
Derive why perfectly separable data breaks MLE for logistic regression.
If a hyperplane perfectly separates the classes, likelihood keeps increasing as ‖w‖ grows, because larger ‖w‖ pushes every z further from 0, driving every predicted probability closer to the correct label's extreme (0 or 1). Since likelihood has no maximum at finite w, gradient-based optimization diverges unless a regularization penalty (like L2) caps ‖w‖.
What replaces the sigmoid when there are more than two classes?
Softmax — it generalizes the sigmoid so that outputs across all classes are non-negative and sum to exactly 1, which the sigmoid alone cannot guarantee when applied independently per class.
